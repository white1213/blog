一个博客的诞生：从零到全自动

为什么想搭个博客

我看过两百多部电影，评分都记在豆瓣；跑了七十多次步，记录在 Keep 里；Steam 上七百多个小时的游戏时长；QQ 音乐里躺着五百多首歌。

这些都是我一个一个攒出来的，但每次想翻翻的时候就得开四五个 App，各看各的。而且说难听点，这些数据都在别人服务器上，人家想怎么改就怎么改。

所以我想要一个自己的地方，把这些东西都收回来。顺便能写点东西。

选型和第一天上线

生成器选了 Hugo。理由没什么高大上的：没有数据库没有后端，整个网站就是一堆文件，推到 GitHub Pages 就能访问。数据天然就在我自己的 Git 仓库里，这很符合我的目的。

主题用了「惊蛰」，国产的，设计干净，而且自带观影页和运动页的骨架，正好是我想放数据的地方。

第一天晚上就把站部署上线了。没有服务器要买，没有环境要配，push 完过几分钟网址就能打开。那会儿页面还是空的，但那种「这就是我的站」的感觉挺好的。

把数据一条条搬回来

之后几天主要干这个，把四个平台的数据接进来。

观影页同步豆瓣，写了个脚本把看过列表和海报都抓过来。现在的观影墙是一面海报墙，打过分的电影角上会带评分。

运动页接了 Keep 的历史跑步，从导出数据转成站里要的格式。转完之后我发现，以前在 Keep 里只能一次一次看记录，现在九个月的数据全摊在面前：累计里程、年度目标进度、这个月比上个月跑得多还是少、最常跑的距离配速有没有变快。数据是同一份数据，看起来的感觉完全不一样了。

音乐页同步了 QQ 音乐歌单，513 首歌连专辑封面一起过来了。游戏页接的 Steam，玩过的 40 款游戏按时长排开，谁玩得多谁的进度条就长。

然后是自动化。现在每天凌晨有三个 GitHub Actions 会依次跑：四点二十同步豆瓣，四点三十七刷新歌单，五点十分拉 Steam。我在睡觉，博客在干活。跑完步看完电影，页面过一会儿自己就更新了，不用管。

顺便造了个写作后台

写文章这件事本身也被我改造了。博客有个不放在导航里的隐藏页面，是个浏览器里的 Markdown 编辑器：写完直接发到仓库，可以导入现成的 .md，可以插图（浏览器里自动压成 WebP 再传），也能改和删已经发的文章。

你现在看的这篇就是在里面写的。自己给自己造生产工具，还挺有意思的。

AI 协作：这次是真的边聊边建

要诚实说，这个博客不是我一个人写的，大部分代码是和 AI 一起弄的。同步脚本、页面模板、CSS，都是我说想要什么，AI 来写，我看了效果再提意见。页面上那些视觉细节，海报墙窄屏放几列、导航栏的间距、怎么把正文宽度突破掉，全是一句一句「左边留白太多了」「间距不对」这样磨出来的。碰到我不懂的，比如 GitHub Actions 的权限、Git 的 API，AI 直接调研完给我方案，我选一个。

我原来以为搭个站至少得会写代码。实际下来感觉门槛变了：你不需要看懂 Hugo 的模板语法，但你得知道海报墙在手机上应该放几列、页面留白多少算舒服——这些判断还是你自己的，AI 替不了。

踩过的坑（点到为止）

几天下来坑不少，说几个印象深的。

中文 Windows 的编码是个老雷。往 GitHub API 推带中文的内容，shell 会把 UTF-8 当 GBK 发出去，远端直接报 400。后来干脆不走 shell 拼内容。

Hugo 有个未来日期的坑：文章日期不带时区的话按 UTC 零点算，北京时间早上发的文章，当天会被静默不渲染。我盯着「明明发了文章首页却没有」看了半天，查出来是这么个原因。

本来想让博客走 Cloudflare Worker 做发布，省掉 token，结果实测 workers.dev 这个域名在国内被污染了，方案只能扔掉，退回 GitHub API 直连。

还有一次 GitHub Pages 的部署接口一直报 500，站点在旧版本上卡了十几个小时。最后把发布链路改了：本地构建好直接推到 gh-pages 分支，绕开出问题的接口。发布链路最好留一条备用通道，这个教训算是记住了。

这些坑有个共同点：都是「看起来成功了，但某处悄悄坏了」的时候才发现的。静态博客虽然简单，但本地构建、API、CI、CDN 缓存这一串，每一环都可能坑你一下。

现在的样子

现在的首页像个小门户：头像下面一行统计，写了多少文章、看了多少电影、跑了多少公里、听了多少首歌、玩了多少小时游戏。每个数字点进去都是个完整的页面。

功能差不多够用了，接下来该往里面装内容了。这篇算是开头。
